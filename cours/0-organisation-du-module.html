Le module

Organisation du module

Pourquoi ce module ?

  • Beaucoup de projets informatiques dépassent leur budget ou leurs délais. La cause est rarement technique : besoin mal compris, tâches oubliées, équipe mal coordonnée
  • En entreprise, vous travaillerez toujours en équipe, avec un client, des échéances et des outils partagés
  • Les projets de groupe de votre formation commencent bientôt. Autant prendre tout de suite les bons réflexes
Ce module ne demande aucune ligne de code. On apprend à organiser un projet, à se répartir le travail et à garder une trace de tout ce que l'équipe produit.
Les études du Standish Group (rapport CHAOS) placent chaque année une large part des projets informatiques en dépassement de budget ou de délai. Rassurer : aucun prérequis technique. Le projet produit des documents, pas du code.

Objectifs du module

À l'issue du module, vous serez capables de :

  • Cadrer un projet : comprendre le besoin d'un client, fixer les objectifs, les livrables et les jalons
  • Choisir une méthode : cycle en V ou méthode agile (Scrum, Kanban)
  • Planifier et suivre : découper en tâches, estimer, suivre l'avancement sur un tableau partagé
  • Collaborer avec Git et GitHub : versionner les documents de l'équipe, proposer et relire des modifications
  • Rendre compte : présenter l'avancement d'un projet à l'oral

Programme

Cours 1 – Gérer un projet

Projet, objectifs, livrables, jalons, acteurs, cycle de vie, cycle en V, agilité, Scrum et Kanban

Cours 2 – Git et GitHub

Versionner, commit, branches, pull request, conflits, issues et suivi du projet sur GitHub

Atelier 1 – Simuler un projet

Un client, un besoin flou, une équipe : on cadre, on découpe, on estime et on planifie sur Trello

Atelier 2 – Collaborer sur GitHub

Le même projet passe sur GitHub : issues, documents de l'équipe, pull requests et soutenance

Projet et soutenance

Livrables du groupe · 12 points

  • Besoin du client reformulé
  • Backlog estimé et planifié
  • Tableau Trello à jour
  • Dépôt GitHub : issues, documents, pull requests, suivi du projet
  • Rétrospective
  • README du dépôt, rédigé en Markdown

Soutenance · 8 points · 10 min

  • 5 min : présentation du projet par toute l'équipe
  • Puis une question à chacun sur le travail du groupe, sans IA
  • Clermont-Ferrand présente sur Teams en partageant son écran

La grille détaillée est dans l'énoncé du projet.

L'IA générative : autorisée, à une condition

  • ChatGPT, Claude, Le Chat… peuvent vous aider à reformuler ou relire un document
  • Les décisions restent celles de l'équipe : le besoin, les priorités, les estimations
  • Déclarez votre usage dans le README : quels outils, pour quoi faire
  • La soutenance et l'examen se font sans IA
  • Un document que personne dans l'équipe ne sait expliquer n'est pas compté
  • Ne collez jamais dans une IA des informations confidentielles d'un client
Conseil : utilisez l'IA comme un relecteur, pas comme un auteur.
